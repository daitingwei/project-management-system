# 权限验证流程图

## 整体架构

```
用户登录 → Token 生成 → 请求携带 Token → 权限中间件验证 → gRPC 调用 → 数据库查询 → 返回权限节点 → 验证通过/失败
```

## 详细流程

### 1. 登录阶段
```
前端请求
  ↓
project-user 服务 (login_service.go)
  ↓
验证账号密码
  ↓
查询 ms_member 表
  ↓
查询 ms_member_account 表 (获取 authorize 字段)
  ↓
查询 ms_organization 表 (获取组织信息)
  ↓
生成 Token (包含 memberId, organizationCode)
  ↓
返回 Token 和权限信息给前端
```

### 2. 请求验证阶段
```
前端请求 (携带 Token)
  ↓
project-api 服务 (auth_midd.go)
  ↓
Token 解析 (获取 memberId)
  ↓
调用 Auth.GetAuthNodes(memberId)
  ↓
gRPC 调用 project-project 服务
  ↓
project-project (auth_service.go)
  ↓
AuthNodesByMemberId(memberId)
  ↓
AuthNodes(memberId) 方法
  ↓
查询 ms_member_account 表 (获取 authorize="admin")
  ↓
根据 authorize 类型查询 ms_project_auth 表 (获取 auth.id=1)
  ↓
查询 ms_project_auth_node 表 (获取所有权限节点)
  ↓
返回权限节点列表给 project-api
  ↓
检查请求 URI 是否在权限节点列表中
  ↓
是 → 放行请求
  ↓
否 → 返回"无权限操作"
```

## 关键代码调用链

```
auth_midd.go:Auth()
  └─> auth.go:GetAuthNodes(c)
        └─> auth_service.go:AuthNodesByMemberId(ctx, msg)
              └─> project_auth.go:AuthNodes(memberId)
                    ├─> accountDomain.FindAccount(memberId)
                    │     └─> accountRepo.FindByMemberId(memberId)
                    │           └─> SELECT * FROM ms_member_account WHERE member_code=?
                    │
                    ├─> projectAuthRepo.FindAuthByType(authorize)
                    │     └─> SELECT * FROM ms_project_auth WHERE type=?
                    │
                    └─> projectAuthNodeDomain.AuthNodeList(auth.Id)
                          └─> SELECT node FROM ms_project_auth_node WHERE auth=?
```

## 数据库表关系

```
ms_member (成员表)
  │
  ├─ id (成员 ID)
  │
ms_member_account (成员账户表)
  ├─ member_code (关联 ms_member.id)
  ├─ organization_code (关联 ms_organization.id)
  ├─ authorize (权限类型："admin" 或 "member")
  │
ms_project_auth (权限角色表)
  ├─ id (权限角色 ID)
  ├─ type (权限类型："admin" 或 "member")
  ├─ organization_code (关联 ms_organization.id)
  │
ms_project_auth_node (权限节点表)
  ├─ auth (关联 ms_project_auth.id)
  ├─ node (权限节点路径，如 "project/project/index")
```

## 修复前后对比

### 修复前 (错误)
```
ms_member_account.authorize = "admin" (字符串)
  ↓
strconv.ParseInt("admin", 10, 64)  // 解析失败
  ↓
authId = 0
  ↓
SELECT node FROM ms_project_auth_node WHERE auth = 0
  ↓
返回空列表 []
  ↓
权限验证失败 → "无权限操作"
```

### 修复后 (正确)
```
ms_member_account.authorize = "admin" (字符串)
  ↓
SELECT * FROM ms_project_auth WHERE type = "admin"
  ↓
auth.Id = 1
  ↓
SELECT node FROM ms_project_auth_node WHERE auth = 1
  ↓
返回 122 个权限节点
  ↓
权限验证通过 → 放行请求
```

## 常见问题排查

### 问题 1: 显示"无权限操作"
**原因**: 
- ms_member_account.authorize 字段值不正确
- ms_project_auth 表中没有对应的权限角色
- ms_project_auth_node 表中没有权限节点

**排查步骤**:
1. 检查 ms_member_account.authorize 字段值 ("admin" 或 "member")
2. 检查 ms_project_auth 表是否有对应的 type
3. 检查 ms_project_auth_node 表是否有对应的 auth 节点

### 问题 2: gRPC 连接失败
**原因**:
- project-project 服务未启动
- etcd 服务未启动
- 服务注册失败

**排查步骤**:
1. 检查 project-project 服务是否运行
2. 检查 etcd 服务是否正常
3. 查看服务日志

### 问题 3: Token 验证失败
**原因**:
- Token 过期
- Token 格式错误
- memberId 解析失败

**排查步骤**:
1. 重新登录获取新 Token
2. 检查 Token 格式
3. 查看 project-api 日志

## 最佳实践

1. **初始化权限配置**: 使用 `权限配置标准.sql` 脚本初始化权限
2. **统一权限类型**: 使用 "admin" 和 "member" 两种标准类型
3. **定期备份**: 定期备份权限配置数据
4. **权限审计**: 定期检查权限配置是否合理
5. **服务监控**: 监控 gRPC 服务状态，确保权限服务可用
